Zoho Subscriptions to Zoho CRM, and a Directory Merged From Three Sources

Three contracts for one client between 2018 and 2020: a Zoho Subscriptions webhook updating Zoho CRM through AWS Lambda, and a nightly merge that turned three separate provider files into one clean directory listing on their website.

zoho crmzoho subscriptionsaws lambdawebhookspythondata merge

What the client had

A membership business running on Zoho. Payments and renewals lived in Zoho Subscriptions. Customers, notes and sales activity lived in Zoho CRM. The two did not talk to each other, so when somebody paid, renewed or cancelled, a person had to open CRM and change the record by hand. That person was not always fast, and sometimes not there at all.

Separately, the directory on their website was assembled by hand every time it changed. One file came from a partner over SFTP, one came out of Zoho Reports, and the current list came out of the website's own database. Someone compared them in Excel and uploaded the result.

What I built

  • A webhook on AWS Lambda between Zoho Subscriptions and Zoho CRM. A subscription event fires, Lambda receives it, and the matching CRM record is updated the same minute. No server to keep running, and no queue to babysit.
  • A repeatable merge for the three source files. Download, normalise the columns, compare against what the website already has, and produce one clean file: new rows, changed rows and rows that disappeared, each marked. The Excel afternoon became a script.
  • Checks before anything is written. A record that looks wrong, a total that does not match, or a file that arrived half-written stops the run and says why, instead of quietly overwriting good data with bad.

Why it lasted

Three contracts with the same client between 2018 and 2020, because each piece was small and testable on its own. The integration is still the pattern I use for CRM work today: one event, one handler, one record updated, with the event's own id stored so that the same event arriving twice changes nothing.

Where this fits

If your CRM, your billing and your website each hold a different version of the truth, the fix is rarely a new platform. It is a small, boring piece of code between them that runs every time and tells you when it cannot.
