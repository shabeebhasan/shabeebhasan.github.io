Video at Serverless Scale: FFmpeg on AWS Lambda

Five years and seven contracts with one client: FFmpeg encoding pipelines on Lambda, auto-scaling EC2 for the heavy jobs, and the operational discipline to keep media infrastructure boring.

aws lambdaffmpegec2 auto-scalings3 / api gatewaymedia pipelines

The Brief

In 2016, running FFmpeg inside AWS Lambda was an odd idea. The runtime was constrained, binaries had to be packaged by hand, and most teams defaulted to always-on servers. A client with a media product wanted encoding that cost nothing while idle and scaled instantly under load.

What I Built

  • FFmpeg-on-Lambda encoding: packaged binaries, tuned memory/duration trade-offs, S3 in, S3 out, API Gateway in front.
  • An EC2 overflow tier for jobs beyond Lambda's limits, scaled up and torn down automatically.
  • Successive revisions across seven contracts as formats, volumes and AWS itself changed. The same client returning from 2016 to 2021.
  • Adjacent serverless work the pattern unlocked: ImageMagick GIF pipelines, Python ETL, DynamoDB backends, Zoho integrations.

Why It Holds Up

Media infrastructure earns trust by being boring: predictable costs, observable failures, retries that work. The measure of this system is not a benchmark. It is a client who came back seven times over five years to grow it.
